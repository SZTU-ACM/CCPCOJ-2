## 1. 总体流程

组织一场 XCPC 标准赛，推荐按“赛前配置、赛中运行、赛后闭幕”三段推进。

| 阶段 | 关键任务 | 主要产出 |
| --- | --- | --- |
| 赛前配置 | 创建比赛、导入题目、生成队伍与工作人员账号、抽签、打印密码条 | 可登录的比赛、完整账号表、座位表、题目与评测配置 |
| 赛中运行 | 打印服务、气球服务、榜单展示、直播叠加 | 稳定的现场服务与可视化展示 |
| 赛后闭幕 | 获奖信息导出、滚榜、照片与离线包准备 | 获奖名单、滚榜展示、闭幕式资料 |

建议在正式比赛前至少完整演练一次以下流程：

- 题目导入与测试评测。
- 队伍账号生成、导入、登录。
- 机位抽签与结果导出。
- 打印员账号、气球账号、直播账号登录。
- 大屏榜单与 RankRoll 滚榜。

## 2. 登录与角色

### 2.1 登录入口

系统中通常有两类登录入口：

- 管理员登录：在左侧菜单栏任意空白区域快速三击鼠标，打开管理员登录框。
- 比赛内登录：进入比赛主页后，在公告区域使用比赛内账号登录。

![alt text](<user_doc_image/Frame 1.png>)

### 2.2 常见角色速查

| 角色 | 用途 | 使用时机 |
| --- | --- | --- |
| 系统管理员 | 创建比赛、导入题目、生成账号、导出数据 | 赛前、赛后 |
| 队伍账号 | 参赛队伍登录比赛 | 热身赛、正式赛 |
| 打印员 printer | 处理选手提交的打印请求 | 赛中 |
| 气球管理员 balloon_manager | 监管气球任务，必要时分配或撤销任务 | 赛中 |
| 气球配送员 balloon_sender | 拉取并完成气球配送任务 | 赛中 |
| 直播 watcher | 进入直播控制台，生成 OBS 叠加层链接 | 赛中 |
| 比赛 admin / 监考员 | 用于现场监管、闭幕式滚榜等 | 赛中、闭幕式 |

## 3. 赛前配置

### 3.1 创建比赛

在后台添加比赛时，比赛类型请选择 **Standard**。


![alt text](<user_doc_image/Frame 2.png>)


#### 获奖比例设置规则

获奖比例字段支持两种写法：

1. 按百分比计算
2. 固定数量


### 3.2 添加题目

题面支持 Markdown 与 LaTeX 公式，后台会通过 Pandoc 编译。常规题面可直接使用 Markdown 编写，数学公式按系统支持的 LaTeX 写法填写。

1. 先创建题目。
2. 进入题目编辑页面。
3. 上传图片附件。
4. 使用上传列表中复制出的相对路径插入题面，不需要额外补 URL。

![alt text](<user_doc_image/Frame 3.png>)

![alt text](<user_doc_image/Frame 4.png>)

#### LaTeX 题面格式

系统支持基础 LaTeX 题面。若某一部分需要按 LaTeX 解析，可在该部分开头单独写一行：

```text
__LATEX__
```

随后即可使用基础 LaTeX 语法，例如 `\textbf{}`、`\includegraphics{}` 等。具体可用命令以当前部署版本为准。

### 3.3 Polygon 题目转换器

系统提供 Polygon 题目包转换功能，可将 [Polygon](https://polygon.codeforces.com/) 打包出的题目转换为 CSGOJ 导入格式。

推荐流程如下：

1. 打开 **Parse Polygon Zip**。
2. 上传 Polygon 导出的 zip 包。
3. 点击 **Help** 查看系统要求的 Polygon 目录结构。
4. 解析完成后，勾选需要导出的题目。
5. 点击 **Pack Selected To CSGOJ**，生成 CSGOJ 可导入的题目包。

![alt text](<user_doc_image/Frame 11.png>)

#### Special Judge 开关

Polygon 通常会为每道题生成 `check.cpp`。导出时请根据题目是否需要 Special Judge 调整对应列的开关：

- 开启：导出包含 `tpj.cc` 的 Special Judge 题目包。
- 关闭：按普通题目导出。

Special Judge 的具体文件规则见下一节。

### 3.4 Special Judge

如题目需要自定义判题，请将 Special Judge 代码与评测数据一同上传，并在题目设置中勾选 **Special Judge**。

目前建议优先使用基于 testlib 的方式。

#### 方式一：基于 testlib，推荐

使用 testlib 时，请上传文件名严格为 `tpj.cc` 的判题程序。评测机会自动编译该文件。

请注意：

- 文件名必须是 `tpj.cc`。
- 仅支持 AC 与 WA 两类结果。
- 非 AC 的情况会按 WA 处理。
- 使用 `tpj.cc` 时，不要同时上传 `spj.cc`。

浮点误差判定示例：

```cpp
#include "testlib.h"
#include <cmath>

const double eps = 1e-6;

int main(int argc, char* argv[]) {
    registerTestlibCmd(argc, argv);

    while (!ans.seekEof()) {
        double expected = ans.readDouble();
        double actual = ouf.readDouble();

        if (std::fabs(expected - actual) > eps) {
            quitf(_wa, "expected %.6f but found %.6f", expected, actual);
        }
    }

    quitf(_ok, "accepted");
}
```

#### 方式二：基于 OJ 原生 SPJ

原生 SPJ 请上传文件名严格为 `spj.cc` 的判题程序。

请注意：

- 文件名必须是 `spj.cc`。
- 仅支持 AC 与 WA 两类结果。
- 非 AC 的情况会按 WA 处理。
- 如果已经使用 `tpj.cc`，请不要再上传 `spj.cc`。

浮点误差判定示例：

```cpp
#include <cstdio>
#include <cmath>

#define AC 0
#define WA 1

const double eps = 1e-6;
char extra[100000];

int main(int argc, char** argv) {
    FILE* input = fopen(argv[1], "r");   // 标准输入
    FILE* answer = fopen(argv[2], "r");  // 标准答案
    FILE* user = fopen(argv[3], "r");    // 用户输出

    double expected, actual;
    while (fscanf(answer, "%lf", &expected) != EOF) {
        if (fscanf(user, "%lf", &actual) != 1) return WA;
        if (std::fabs(expected - actual) > eps) return WA;
    }

    if (fscanf(user, "%s", extra) == 1) return WA;

    fclose(input);
    fclose(answer);
    fclose(user);
    return AC;
}
```

### 3.5 生成队伍账号

队伍账号有两种推荐生成方式：直接导入队伍信息，或结合机位抽签后导入。

#### 方式一：提前整理队伍信息后直接导入

适用于赛前已经确定队伍信息、无需现场抽签导入的场景。

操作入口：

```text
/cpcsys/admin/contest_teamgen?cid=xxxx
```

其中 `xxxx` 替换为当前比赛 ID。

进入页面后点击 **Help** 查看导入格式。建议先按模板整理 Excel 或表格，再导入比赛。

![alt text](<user_doc_image/Frame 5.png>)

#### 方式二：结合抽签流程导入

适用于需要在开幕式或赛前进行机位抽签的场景。

先生成一批只包含 team 编号与密码的空账号。生成时建议使用两个参数：

| 参数 | 建议填写 |
| --- | --- |
| 参数 1 | 队伍数量加约 50，留出冗余 |
| 参数 2 | 密码种子数字 |


### 3.6 机位抽签

抽签地址：

```text
http://[OJ地址]/ojtool/seatdraw
```

如果只需要抽签结果，不需要将结果导入比赛，可以不登录账号直接使用抽签模块。

#### 推荐协作流程

以下流程适用于“承办方现场抽签，管理员随后用相同数据导入比赛”的场景：

1. 承办方提前按页面提示格式准备房间与队伍信息表。
2. 管理员保留一份完全一致的表格。
3. 承办方在开幕式执行抽签。热身赛前建议先模拟演练。
4. 抽签结束后，承办方将页面显示的随机种子发送给管理员。
5. 管理员使用同一份表格和同一个随机种子，在管理端复现相同抽签结果。
6. 管理员将抽签结果导入对应比赛。
7. 承办方按单位序导出抽签结果，并发布给参赛队伍，便于队伍找座位。

![alt text](<user_doc_image/Frame 6.png>)

### 3.7 封装与分发密码

队伍账号生成后，可在队伍生成页面通过表格右上角的 **XLSX** 按钮下载密码条打印表。

下载文件中通常包含：

- 适合裁剪分发的密码条。
- 不同排版方式的打印子表。
- 适合发布或归档的账号表。

建议将密码分发流程提前制度化：

- 打印后按单位、队伍或座位号排序。
- 密码条封装后在赛前统一交接。
- 保留一份管理员备查表，避免现场遗失后无法快速补发。

### 3.8 生成工作人员账号

工作人员账号可在以下入口生成：

```text
/cpcsys/admin/contest_staffgen?cid=xxxx
```

其中 `xxxx` 替换为当前比赛 ID。

推荐准备以下人员信息：

- 打印员名单。
- 气球员名单。
- 学号、姓名、职责等字段。

操作建议：

1. 承办方提前整理工作人员 Excel。
2. 管理员在 StaffGen 页面生成账号。
3. 额外生成两个裁判或监考员 admin 账号，一个用于现场裁判，一个用于赛后滚榜。
4. 管理员赛前将工作人员账号交给承办方。
5. 承办方将账号分发给对应志愿者。

![alt text](<user_doc_image/Frame 7.png>)

补充建议：

- 可使用页面中的 **Gen Template** 按钮生成模板，再复制到 Excel 中编辑。
- `balloon_sender` 建议为每位气球配送员单独准备账号，方便追踪任务领取与完成情况。

## 4. 赛中运行

### 4.1 打印员 printer

打印服务建议使用一台连接打印机的 Windows 电脑。将目标打印机设置为系统默认打印机后，打印员在该电脑上打开 OJ 对应比赛，并使用 printer 账号登录。

如果现场有多台打印机，请为每台打印机准备：

- 一台对应电脑。
- 一个 printer 账号。
- 一套清晰的打印区域或任务分工。

![alt text](<user_doc_image/Frame 8.png>)

操作建议：

- 比赛前期可先使用手动模式，确认打印机、纸张、网络稳定。
- 比赛中后期流程稳定后，可按现场需要开启自动模式。
- 打印员务必逐项阅读页面提示，确认浏览器、默认打印机和权限均已配置正确。

### 4.2 气球管理员 balloon_manager

气球管理员主要负责全局监管气球发送情况，可观察任务流转，也可手动分配或撤销部分任务。

在气球管理界面按 **A** 键可切换管理模式。

#### 模式一：分配模式 Task Assign Mode

该模式主要用于观察与核对。气球配送员领取任务、标记任务等操作，都可在此模式中看到。

在必要时，管理员也可以点击某个气球任务，在弹窗中将任务分配给指定 `balloon_sender`。

![alt text](<user_doc_image/气球队列.png>)

#### 模式二：标记模式 Task Finish Mode

该模式适用于线下纸条、线上文档任务队列等集中派发方式。管理员点击任务后，即可将任务标记为已下达。

该模式可以不依赖 `balloon_sender` 账号。

### 4.3 气球配送员 balloon_sender

气球配送员可使用手机连接赛场 Wi-Fi，通过系统浏览器访问 OJ，并登录自己的 `balloon_sender` 账号。

使用建议：

- 推荐使用手机原生浏览器。
- 不建议使用微信、QQ 等内置浏览器。
- 配送员在页面中拉取自己负责区域的气球任务。
- 气球送达后，双击对应任务标记为已发放。
- 如需退还任务，可双击未发气球的时间列。


### 4.4 大屏展示

大屏榜单可以使用外榜，也可以使用内网的 Dynamic Rank。Dynamic Rank 通常可在 Ranklist 页面中通过蓝色 **Dynamic Rank** 按钮进入。

常用快捷键：

| 操作 | 快捷键 |
| --- | --- |
| 自动刷新 | 按 `A` |
| 自动滚屏 | 按 `B` |
| 浏览器全屏 | 按 `F11` |

建议在正式比赛前确认：

- 大屏浏览器缩放比例合适。
- 字体、队名、题目列完整显示。
- 自动刷新和自动滚屏可正常工作。
- 内外网访问策略符合现场网络环境。

### 4.5 直播

直播功能需要先在 StaffGen 中生成 `watcher` 账号。该账号登录后，可在菜单中进入 **直播 Live** 控制台。

推荐流程：

1. 使用 `watcher` 账号登录比赛。
2. 点击菜单中的 **直播 Live**。
3. 在直播控制台中配置展示参数和菜单开关。
4. 点击 **Open Overlay**，获取直播 token 链接。
5. 在 OBS Studio 中添加“浏览器”源。
6. 将 token 链接填入浏览器源，叠加比赛数据到直播画面。

## 5. 赛后与闭幕

### 5.1 获奖信息整理

赛后由管理员在后台下载获奖信息表。导出前请先确认：

- 比赛已经结束。
- Status 页面中没有未判完的提交。
- 获奖页面已刷新到最新数据。

承办方可基于导出的获奖信息表继续处理证书、奖牌、新闻稿和归档材料。

![alt text](<user_doc_image/Frame 9.png>)

### 5.2 滚榜颁奖 RankRoll

闭幕式滚榜通常由承办方使用比赛内的监考员 admin 账号完成。管理员可提前准备一个比赛内 admin 账号交给承办方。

基本流程：

1. 闭幕式电脑访问对应比赛。
2. 使用比赛内 admin 账号登录。
3. 点击 **RankRoll** 进入滚榜页面。
4. 全屏展示并按现场流程开始滚榜。

![alt text](<user_doc_image/Frame 12.png>)

#### 队伍照片

滚榜页面右上方通常有 **队伍照片** 按钮，可进入队伍照片管理页面。

照片上传方式：

| 方式 | 操作说明 |
| --- | --- |
| 单个上传 | 在对应队伍行直接上传图片 |
| 批量上传 | 准备所有队伍 `.jpg` 文件，文件名使用队伍比赛账号名，例如 `team001.jpg`，选择全部文件后批量上传 |

照片建议：

- 推荐宽高比为 3:2。
- 比例略有误差通常可以接受，系统会自动裁剪。
- 不建议上传比例差异过大的图片。
- 如果滚榜电脑到服务器网络不稳定，建议提前完整滚榜一次，让浏览器缓存队伍照片。

#### 滚榜界面缩放

启动滚榜并全屏后，可通过以下方式调整页面缩放：

- `Ctrl` + 鼠标滚轮。
- `Ctrl` + `+` / `-`。

建议以屏幕中同时显示约 12 支队伍为参考，并确保所有数字完整显示，不出现省略号。

### 5.3 离线滚榜

如果闭幕式现场无法稳定访问服务器，可使用滚榜页面右上角的 **打包下载** 功能，将滚榜所需数据打包到本地，再拷贝到离线环境中使用。


## 6. 检查清单

### 6.1 赛前检查

- [ ] 比赛类型已设置为 **Standard**。
- [ ] 比赛时间、封榜时间、榜单设置已确认。
- [ ] 获奖比例或固定名额已确认。
- [ ] 题面、样例、附件图片均可正常显示。
- [ ] 评测数据已上传，普通题与 Special Judge 题均已测试。
- [ ] 队伍账号已生成、导入并抽查登录。
- [ ] 机位抽签数据已演练，随机种子复现正常。
- [ ] 密码条已打印、封装并完成交接。
- [ ] 打印员、气球员、直播 watcher、比赛 admin 账号已生成。
- [ ] 大屏、打印机、OBS、现场网络均已测试。

### 6.2 赛中检查

- [ ] 打印管理页面正常接收任务。
- [ ] 打印机纸张、墨粉、默认打印机设置正常。
- [ ] 气球任务可正常生成、领取、完成或退还。
- [ ] Ranklist 或 Dynamic Rank 可正常刷新。
- [ ] 直播叠加层在 OBS 中显示正常。
- [ ] 管理员持续关注评测队列，确认无异常堆积。

### 6.3 赛后检查

- [ ] 比赛已结束。
- [ ] Status 中没有未判完的提交。
- [ ] 获奖页面已刷新并导出最新表格。
- [ ] 滚榜账号可登录，RankRoll 页面可打开。
- [ ] 队伍照片已上传并完成缓存预加载。
- [ ] 如需离线滚榜，已完成打包下载并在目标电脑测试。

### 6.4 常见风险提示

- Special Judge 文件名必须严格匹配：testlib 使用 `tpj.cc`，原生 SPJ 使用 `spj.cc`。
- 使用 `tpj.cc` 时不要同时上传 `spj.cc`。
- 现场抽签必须保证承办方与管理员使用完全一致的表格和随机种子。
- 密码条打印后应留一份管理员备查表。
- 气球配送员建议使用原生浏览器，避免内置浏览器导致交互异常。
- 闭幕式滚榜前建议至少完整预演一次，包括照片加载、页面缩放和大屏显示。
